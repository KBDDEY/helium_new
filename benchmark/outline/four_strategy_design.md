# 四个调度策略组合讨论稿 v2

当前接续入口为 [自适应调度策略讨论稿 v3（五个启发式策略）](five_strategy_design.md)。v3 将原尾部第四策略改称第五策略，并将原顺序全单卡回退列为第四策略。本稿保留 v2 当时的四策略编号。

记录日期为 2026-11-17。当前方案由三个互斥的基础策略和一个可叠加的尾部策略组成，作为后续讨论与实现的接续依据。前三个基础策略的完整均值模型证明保存在 [2026-11-13 三类策略 v1](three_class_strategy.md)。

本文记录策略设计。现有代码仍包含早期等待策略，四策略组合与运行期动态扩卡接口均待实现。

**第一、二、三策略按初始队列互斥匹配，第四策略在全部任务启动后的尾部阶段独立启用。** 未匹配前三个策略的队列采用原顺序全单卡作为基础安排，也可以叠加第四策略。

一个时段的执行过程为

\[
\text{初始队列}
\longrightarrow
\{\text{第一策略、第二策略、第三策略、全单卡回退}\}
\longrightarrow
\text{全部任务已启动}
\longrightarrow
\text{第四策略尾部扩卡}
\longrightarrow
\text{本时段清队}.
\]

所有任务在时段起点一次就绪，K 张卡起点均可用。当前分析以单时段为范围，进入尾部后没有新任务到达。卡由调度器独占分配给任务，各任务保留已有资源；第四策略只追加空卡，任务完成后释放它当前持有的全部卡。

主指标为本时段清队时间 C。全单卡基线使用同一任务集、同一原始顺序和 K 张卡，有空卡就启动队头任务。资源时间恒等式提供累计占卡与空卡的分析口径。

| 符号 | 含义 |
|---|---|
| P | parallel，高负载、分卡收益较高 |
| D | debate，负载较低、分卡收益较小 |
| I | iterative，始终单卡 |
| S | D 和 I 的合称 |
| K | 实际启用的卡数 |
| p、s | 初始 P 数量和 S 数量 |
| n0 | 初始任务总数，n0 = p + s |
| n | 当前尚未启动的任务数，包含队头，排除运行中的任务 |
| F | 当前空卡数 |
| C_P、C_D | P、D 的有效卡数上限，取 k_max 配置值与 K 的较小值 |
| w | 第二、第三策略的初始 P 分卡数 |
| q、r | p = qK + r，q = floor(p/K)，r = p mod K |
| k_wait | 第四策略优先补齐的累计卡数目标 |
| a | 第四策略的有效首档目标，a = min(k_wait, C_P) |
| k_i | 某个运行任务当前持有的卡数 |
| t_i | 任务实际开始运行的时刻 |
| T1、Tw | 固定均值模型中 P 单卡和 w 卡的代表持卡时长 |
| τ | S 在相应允许配置下的代表持卡时长上界 |

k_max、w、k_wait 均作为 config.py 的配置输入。w 要满足 2 ≤ w ≤ C_P，配置字段名留待实现时确定。k_wait 为正整数，本版在第四策略中将它用于首档补卡目标。w 和 k_wait 分别服务于起点分卡与尾部扩卡，可以取相同数值，但用途独立。示例中 w = 2、k_wait = 2，策略本身不固定为两卡。

已有 K_WAIT_TABLE 仍属于早期等待策略代码，后续接入第四策略时需要按本文约定明确其参数含义。

**前三个基础策略只在时段起点匹配一次。** 判定顺序为第一、第二、第三、全单卡回退，后续队列缩短不重新分类。空队列直接结束。第二、第三策略需要有效的 w。

| 基础策略 | 初始判定条件 | 任务顺序 | 基础分卡规则 |
|---|---|---|---|
| 第一策略 | 1 ≤ n0 ≤ K − 1 | 保留完整原顺序 | 所有任务立即启动，初始富余卡优先给 P，D 使用相应富余，I 单卡 |
| 第二策略 | 第一未匹配，p ≥ 1，wp ≤ K，wp + s ≤ 2K | P 稳定提前 | 所有 P 起点各 w 卡，S 随空卡补位 |
| 第三策略 | 前两者未匹配，q ≥ 1，1 ≤ r < K，wr ≤ K，wr + s ≤ 2K | P 稳定提前 | 起点前 r 个 P 各 w 卡，其余 qK 个 P 与全部 S 单卡补位 |
| 全单卡回退 | 三者均未匹配 | 保留完整原顺序 | 全单卡，有卡立即补位 |

P 稳定提前表示 P 之间保留原相对顺序，D/I 之间保留原有混合相对顺序。第二、第三策略都先启动 P，全部 P 已启动后即可用空卡启动 S。

**第一策略沿用保并发的 FIFO 分配规则。** 初始 n = n0，由准入条件 n0 ≤ K − 1 得到 F = K ≥ n0 + 1，至少有一张富余卡。逐次分配时保持 F ≥ n，每次为后续每个任务保留一张卡。I 分配一张，队头 P 分配

\[
k_P=\min(C_P,F-(n-1)).
\]

队头 D 先计算其后续任务预算

\[
B_{\mathrm{tail}}
=C_Pp_{\mathrm{later}}+d_{\mathrm{later}}+i_{\mathrm{later}},
\]

再分配

\[
k_D=\min(C_D,\max(1,F-B_{\mathrm{tail}})).
\]

每次启动后更新 F、n 和后续预算。最后一个 P 同样立即启动，分配 min(C_P,F)。该规则保证所有任务在起点这一轮获得卡，额外卡来自基线初始空着的 K − n0 张卡。

**第二策略在起点为所有 P 各分 w 张卡。** 剩余 K − wp 张卡用于启动 S，后续继续按 S 原混合顺序补位。I 始终一张，D 保留真富余分卡规则。

令 u 为尚未启动的 S 数量，包含当前队头 D。在 F ≥ 1 时，

\[
k_D=
\begin{cases}
1,&F<u,\\
\min(C_D,F-(u-1)),&F\ge u.
\end{cases}
\]

D 取得额外卡时，为其他待启动 S 各保留一张。每次分配后更新 F、u，继续调度。

**第三策略在起点为前 r 个 P 各分 w 张卡，余下 qK 个 P 全部按单卡执行。** 起点剩余 K − wr 张卡立即启动其中一部分单卡 P，后续每释放几张卡就启动几个尚未启动的单卡 P。所有 P 已启动后，S 按原混合顺序全单卡补位。

第三策略的“后续单卡”描述基础安排。所有 S 也已启动后，第四策略可以继续给运行中的 P 增卡。全单卡回退与第一、第二策略采用相同的尾部衔接方式。

**第四策略的入口是 n = 0，即本时段 P、D、I 全部已经启动。** 运行集合此时可以非空。只有“全部 P 已启动”而仍有 S 排队时，继续执行基础策略。

在首次进入尾部时，以及后续任务完成释放卡、执行层出现可分派工作等资源状态变化时，检查第四策略。增卡对象为仍在运行、尚未达到 C_P 且能够使用新增资源的 P，新增卡接续其后续可分派调用。

分配顺序按任务实际启动时刻 t_i 从晚到早排列。增卡后的任务仍使用最初启动时刻参与排序。同一实际启动时刻的 P，本稿暂按原始队列相对顺序打破并列，这是为使规则确定而补充的可调整细节。

第四策略分两档使用当前空卡。

1. 按上述顺序检查 P，将每个尚未达到 a 的 P 优先补到 a。已经达到或超过 a 的 P 跳过这一档。
2. 每个 P 本次可追加的卡数为 min(F, max(0, a − k_i))，分配后立即更新 F、k_i。
3. 当前能够增卡的 P 已全部达到 a，且还有空卡时，按同样顺序逐个补到 C_P。本次可追加数为 min(F, C_P − k_i)。
4. F 用完就结束本轮。后续有卡释放时重新按这两档规则分配。各任务已有卡继续由该任务持有，任务结束时统一释放。

“先给到 k_wait，再给到 k_max”指先覆盖当前能够使用新增资源且尚未达到首档目标的 P，再使用剩余卡提高分配上限。一张空卡就可以立即追加，达到首档目标不作为开始使用新增卡的条件。

若当前没有可增卡的 P，本轮自然没有分配。第四策略是所有队列共用的尾部规则，实际增卡机会与加速幅度由当时运行状态决定。

例如 K = 5，尾部有两个 P，较早启动的 A 已有两张卡，较晚启动的 B 已有一张，另有两张空卡。设 k_wait = 2、C_P = 4。

| 分配过程 | A 的卡数 | B 的卡数 | 空卡 |
|---|---:|---:|---:|
| 分配前 | 2 | 1 | 2 |
| 首档先给 B 补一张，两个 P 都达到两张 | 2 | 2 | 1 |
| 第二档按晚启动优先，再给 B 一张 | 2 | 3 | 0 |

其余情况按当前卡数计算。当前持卡数已达到或超过 a 的 P 跳过首档，起点获得多卡的 P 同样按当前 k_i 判断。增卡后的总持卡数不超过 C_P。

优先晚启动 P，使用了调度器已经知道的启动时间作为剩余进度的粗略信号。先补齐 k_wait，用于优先覆盖收益较高的卡数区间。当前代表耗时中，P 单卡到双卡节省约19.291秒，双卡到三卡再节省约6.497秒。这提供了优先覆盖两卡的启发依据，运行中实际剩余收益由当时可分派工作决定。

**前三个基础策略的证明先独立成立，再分析第四策略叠加。** 用 C_B 表示单独采用相应基础安排时的清队时间，C_FIFO 表示原顺序全单卡基线。

第一策略在所有任务同时启动、分卡不增加任务自身持卡时长时，有

\[
C_B=\max_i T_i(k_i)\le\max_i T_i(1)=C_{\mathrm{FIFO}}.
\]

第二、第三策略在固定均值模型中使用

\[
B=\max(2\tau,T_w+\tau),
\qquad
2\tau\le T_1,\quad T_w+\tau\le T_1.
\]

第二策略满足

\[
C_B\le B\le T_1\le C_{\mathrm{FIFO}}.
\]

第三策略另使用 0 < Tw < T1，其两组卡分别在 qT1 和 qT1 + Tw 释放给 S，因而

\[
C_B\le qT_1+B\le(q+1)T_1\le C_{\mathrm{FIFO}}.
\]

详细排程与计数证明见 v1。上述界先描述运行中卡数固定的基础执行，第四策略介入后按下述条件衔接。

以基础执行中的任务完成时刻 e_i^B 为参照。第四策略在追加资源不拖慢原执行的模型下，满足

\[
e_i^{B+4}\le e_i^B.
\]

因此

\[
\boxed{
C_{B+4}=\max_i e_i^{B+4}
\le\max_i e_i^B=C_B
}.
\]

第一、第二、第三策略在各自证明条件下，可继续得到

\[
C_{B+4}\le C_B\le C_{\mathrm{FIFO}}.
\]

采用全单卡回退时，C_B = C_FIFO，也可以使用同一个尾部条件保证。这个衔接不要求预先知道最后完成的是哪个 P。

若受益任务缩短了最终拖尾，整队加速。若终点仍由其他任务决定，则可以持平。实现需要保证新增路由、缓存处理与调度开销满足追加资源不拖慢原执行的前提，当前静态整任务 T(k) 数据不能直接给出中途扩卡的具体时间收益。

**动态扩卡仍使用同一个资源时间恒等式。** 令 k_i(t) 为任务在时刻 t 实际持有的卡数，则

\[
W=\sum_i\int_0^C k_i(t)\,dt,
\qquad
W+H=KC.
\]

W 按调度器的卡分配统计，任务取得首张卡之前和释放全部卡之后取 k_i(t) = 0，持卡期间的启动和收尾计入占用；H 为本时段起点到清队期间累计的空卡时间。计算真实 W 时需要使用卡数变化记录，分配占用与 GPU 实际计算利用率采用各自统计口径。

将“基础策略加第四策略”与“仅基础策略”比较，若清队时间持平，则

\[
W_{B+4}-W_B=H_B-H_{B+4}.
\]

新增占卡为正时，对应相同数量的累计空闲减少。清队是否提前仍由最终完成任务决定。

旧第三策略的占卡变化公式

\[
\Delta W=r(wT_w-T_1)
\]

只描述基础策略相对全单卡的变化。叠加第四策略后，使用实际 k_i(t) 积分计算全部变化。

当前初始代表耗时仍采用此前讨论值，单位为秒。

| 类型 | 单卡 | 双卡 | 三卡 |
|---|---:|---:|---:|
| I | 15 | — | — |
| D | 10.5 | 8.5 | 7.9 |
| P | 50.347 | 31.056 | 24.559 |

当 w = 2、τ = 15 时，B = 46.056，T1 − B = 4.291。第二、第三策略的原有均值结论保留其模型范围。I 的15秒目前为代表值，真实上界与波动需要实测核验。

第四策略的实现要让运行任务能够获得新增引擎，并将后续可分派调用路由到获得授权的引擎。现有常驻 vLLM 池提供了资源基础，任务执行进程与 Helium 当前固定的引擎映射还需要扩展接口。当前四策略组合尚未接入运行代码。

后续接续时使用以下关系。

- 第一、第二、第三是起点互斥的基础策略，只匹配一次。
- 第四是全部任务启动后的统一尾部扩卡策略，可叠加到前三类和全单卡回退。
- 第三策略保留起点前 r 个 P 多卡，其余 P 和 S 在基础阶段单卡补位。
- 第四按实际启动时间从晚到早，先覆盖 k_wait，再向 k_max 补齐，只使用已经空闲的卡。
- 所有初始分卡数、尾部目标与分配上限均由配置输入。
- 原基础模型保证与尾部条件保证分别说明，真实清队收益通过实验检验。
